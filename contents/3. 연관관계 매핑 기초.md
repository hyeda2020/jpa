# 3. 연관관계 매핑 기초
- 단방향 연관관계

  ```
  public class Team {
      @Id
      @GeneratedValue
      @Column(name = "team_id")
      private Long teamId;
  }
  
  public class Member {
      ...
      /* Team 클래스와 단방향 연관관계 매핑(다대일) */
      @ManyToOne
      @JoinColumn(name = "team_id")
      private Team team;
  }
  ```
  
- 양방향 연관관계 : 객체의 경우 사실상 단방향 연관관계가 두 개 있는 것과 동일  
  <img width="842" height="504" alt="스크린샷 2026-04-30 223510" src="https://github.com/user-attachments/assets/edfc9575-dc6a-4181-9d04-15e7a1e6e5e4" />
  ```
  @Entity
  public class Member {
      @Id @GeneratedValue
      private Long id;

      @Column(name = "name")
      private String name;
      private int age;

      @ManyToOne
      @JoinColumn(name = "team_id")
      private Team team;
      ...
  }
  ```
  ```
  @Entity
  public class Team {
      @Id @GeneratedValue
      private Long id;

      private String name;

      @OneToMany(mappedBy = "team") // 외래키가 있는 Member.team 을 연관관계 매핑의 주인으로 설정
      List<Member> members = new ArrayList<Member>();
      ...
  }
  ```
  - `Member`와 `Team` 클래스는 N:1 관계
  - DB 상에서는 두 테이블의 `team_id`을 외래키로 쉽게 연관관계 관리가 가능하지만,  
    객체에서의 양방향 연관관계인 경우, 양쪽에 서로 참조 객체가 존재해야 함  
    -> `Member` 클래스에는 참조 필드인 `team`을, 그리고 `Team` 클래스에는 `Member` 클래스를 리스트로 담는 방식으로 구현
  - `mappedBy` : 해당 연관관계의 주인을 설정하는 것으로, 일반적으로는 다대일/일대다 중에서 '다'(Many) 쪽,  
    즉 외래키가 있는 쪽이 연관관계의 주인이 되는 것이 바람직한 구조  
    -> 연관관계의 주인만이 외래 키를 관리(등록, 수정) / 주인이 아닌 쪽은 읽기만 가능  
    -> 주인은 `mappedBy` 속성을 사용하지 않으며, 주인이 아닌 경우만 `mappedBy` 속성으로 주인 지정  
    -> 이를 통해 Member 클래스의 team 을 바꾸면 Member 테이블의 값이 바뀐다고 바로 쉽게 이해할 수 있음  
  - 반드시 양 방향 객체(주인/비주인)에 값을 세팅해줘야 연관관계가 매핑이 됨
  - 연관관계 메서드를 활용하여 양 방향 객체의 값이 자동으로 세팅되도록 하기
    ```
    // Member 클래스에 선언한 연관관계 메서드
    public void changeTeam(Team team) {
        this.team = team;
        team.getMembers().add(this);
    }
    ```
  - 양방향 매핑 시 무한루프 주의!(ex. toString(), lombok, JSON 생성 라이브러리)
    ```
    @Override
    public String toString() {
        return "Member{" +
               "id=" + id +
               "name=" + name +
               "team=" + team +
               "}";
    }
    ```
    - 만약 `Member` 클래스에서 `toString()` 메서드를 오버라이드해서 `team` 필드 값을 문자열로 바꿀 경우,  
      자동으로 `team` 참조 내 담긴 `List<Member> members` 내의 `Member` 클래스 객체 값들을 문자열로 바꾸게 되며,  
      이렇게 무한으로 반복하여 양방향의 두 객체가 문자열로 변환될 수 있음.  
    - 따라서, 이런 양방향 연관관계에서는 가급적 lombok 및 JSON 생성/변환 라이브러리 사용 자제    
      특히, Entity 그 자체를 컨트롤러 외부로 바로 전달하지 말고 DTO로 변환해서 전달하는 방식 권장(무한루프 및 의도치 않은 값 변경 방지)
  - 연관관계 매핑은 가급적 단방향 매핑으로 완료하는 것이 좋으며, 양방향 매핑은 반대 방향으로의 조회 기능이 추가된 것 뿐
