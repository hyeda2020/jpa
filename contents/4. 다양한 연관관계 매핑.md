# 4. 다양한 연관관계 매핑
- 다대일 : `@ManyToOne`
  - 다대일 단방향  
    <img width="715" height="404" alt="스크린샷 2026-05-08 225533" src="https://github.com/user-attachments/assets/08db36e2-6c78-4a5f-bcf7-d6daacf44d35" />  
    ```java
    @Entity
    public class Member {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        @Column(name = "member_id")
        private Long id;

        @Column(name = "name") // 컬럼 매핑
        private String name;

        @ManyToOne
        @JoinColumn(name = "team_id") // Team 클래스의 team_id 컬럼과 조인
        private Team team;
    }
    ```
    ```java
    @Entity
    public class Team {
        @Id
        @GeneratedValue
        @Column(name = "team_id")
        private Long id;

        private String name;
    }
    ```
  - 다대일 양방향  
    <img width="713" height="425" alt="스크린샷 2026-05-08 225542" src="https://github.com/user-attachments/assets/e642092d-27f1-401c-960f-7f1ff0bc9d76" />  
    - 외래키가 있는 쪽이 주인
    - 양쪽을 서로 참조
    ```java
    @Entity
    public class Team {
        @Id
        @GeneratedValue
        @Column(name = "team_id")
        private Long id;

        private String name;
    
        @OneToMany(mappedBy = "team") // 연관관계 주인 설정(Member 클래스의 team 필드)
        private List<Member> members = new ArrayList<>();
    }
    ```
  

- 일대다 : `@OneToMany`
  - 일대다 단방향  
    <img width="741" height="411" alt="스크린샷 2026-05-08 225550" src="https://github.com/user-attachments/assets/3d7819cd-27dd-48e9-90de-89a0a3ad1b28" />  
    - 일대다 단방향은 일(1)이 연관관계의 주인
    - 단, 테이블 일대다 관계는 항상 다(N) 쪽에 외래 키가 있기에  
      객체와 테이블의 이러한 차이 때문에 반대편 테이블의 외래키를 관리하는 구조    
    - `@JoinColumn`을 꼭 사용해야 함  
      (그렇지 않으면 조인 테이블 방식 사용 - 중간 테이블 활용 방식)
    ```java
    @Entity
    public class Member {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        @Column(name = "member_id")
        private Long id;

        @Column(name = "name") // 컬럼 매핑
        private String name;
    }    
    ```
    ```java
    @Entity
    public class Team {
        @Id
        @GeneratedValue
        @Column(name = "team_id")
        private Long id;

        private String name;
    
        @OneToMany
        @JoinColumn(name = "team_id") 
        private List<Member> members = new ArrayList<>();
    }    
    ```
  - 일대다 단방향 매핑의 단점(일대다 단방향 매핑보다는 다대일 양방향 매핑을 사용 권장)
    - 엔티티가 관리하는 외래키가 다른 테이블에 있음
    - 연관관계 관리를 위해 추가로 UPDATE SQL 실행 필요
  - 일대다 양방향  
    <img width="795" height="395" alt="스크린샷 2026-05-08 225557" src="https://github.com/user-attachments/assets/6732f690-0998-4441-a681-e89f75bdb26c" />  
    - 이런 매핑은 공식적으로는 존재하지 않으며, 읽기전용 필드를 사용해서 마치 양방향 매핑처럼 사용하는 방법  
      -> `@JoinColumn(insertable=false, updatable=false)` 활용  
      -> 차라리 다대일 양방향을 사용하는 것 권장
    ```java
    @Entity
    public class Member {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        @Column(name = "member_id")
        private Long id;

        @Column(name = "name") // 컬럼 매핑
        private String name;
    
        @ManyToOne
        @JoinColumn(name = "team_id", insertable=false, updatable=false)
        private Team team;
    }    
    ```
  
- 일대일 : `@OneToOne`
  - 일대일 관계는 그 반대도 일대일
  - 주 테이블이나 대상 테이블 중에 외래키 선택 가능
  - 외래키에 데이터베이스 유니크(UNIQUE) 제약조건 추가
  - 주 테이블에 외래키 단방향

- 일대일 매핑 정리
  - 주 테이블에 외래 키
    - 주 객체가 대상 객체의 참조를 가지는 것 처럼  
      주 테이블에 외래 키를 두고 대상 테이블을 찾음
    - 장점: 주 테이블만 조회해도 대상 테이블에 데이터가 있는지 확인 가능
    - 단점: 값이 없으면 외래 키에 `null` 허용
  - 대상 테이블에 외래 키
    - 대상 테이블에 외래 키가 존재
    - 장점: 주 테이블과 대상 테이블을 일대일에서 일대다 관계로 변경할 때 테이블 구조 유지
    - 단점: 프록시 기능의 한계로 지연 로딩으로 설정해도 항상 즉시 로딩됨
